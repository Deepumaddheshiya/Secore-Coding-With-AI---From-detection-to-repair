# SecureCode AI – Secure Coding: From Detection to Repair

A comprehensive, research-oriented implementation of the empirical study:
> **"Secure coding with AI – from detection to repair"**  
> *Empirical Software Engineering* (2026), Volume 31, Article 93  
> DOI: [10.1007/s10664-026-10812-8](https://doi.org/10.1007/s10664-026-10812-8)

---

## 1. Strict Design & Operational Rules

1. **Zero Paid APIs / Zero API Keys**: No OpenAI, Anthropic, Gemini, or other cloud LLM APIs are used, requested, or required.
2. **Zero Cloud AI Calls**: All inference (if enabled) runs strictly offline via local [Ollama](https://ollama.ai) (`localhost:11434`).
3. **No Fabricated Data**: Clear separation between:
   - **Research Paper Results** (historical data from the 2026 study, marked with amber alerts)
   - **Local Execution Results** (generated by live scanners and repair engines on the host machine)
   - **Unavailable Results** (scanners or tools not installed locally marked explicitly)
4. **All 18 Benchmark Tables Extracted**: Complete inventory of every numbered table in the paper with source page references, categories, and full structural metadata.

---

## 2. Key Features

- **Full Benchmark Inventory**: All 18 tables extracted from the research paper into JSON and CSV (`data/paper_benchmarks.json`, `data/paper_benchmarks.csv`).
- **Dataset Pipeline**: Processing pipeline for DevGPT snapshots (`snapshot_20231012` and `snapshot_20240514`) targeting C, C++, and C# files with deterministic LOC counting, safe path resolution, and metadata deduplication.
- **Static Security Scanner Adapters**: Modular plug-in adapters for **Snyk**, **Semgrep**, **Flawfinder**, and **Cppcheck**. Scanner availability auto-detected at startup.
- **Automated Repair Engine**: Dual-mode repair pipeline featuring:
  - Deterministic AST/regex rule-based repair for top CWEs (CWE-120 `strcpy`/`sprintf`, CWE-327 `srand`, CWE-78 `system`, CWE-665 uninitialized memory).
  - Local Ollama AI repair fallback (`qwen2.5-coder:1.5b` or custom models) with zero cloud calls.
  - Safe patch lifecycle: preview diff &rarr; user approval &rarr; automated file backup &rarr; patch application &rarr; scanner rescan verification &rarr; one-click rollback.
- **Interactive Full-Stack Web Dashboard**: Single-page application built with React, Vite, Tailwind CSS, Lucide icons, and Recharts, featuring 20 dedicated views:
  1. Overview & System Health
  2. Research Paper Benchmark Explorer (All 18 Tables)
  3. DevGPT Dataset Inventory & LOC Analysis
  4. Static Security Scanners Status & Execution
  5. Normalized Security Findings Browser
  6. Vulnerability Review & Triage
  7. Automated AI / Rule Repair Engine & Diffs
  8. Patch Lifecycle & Verification
  9. Paper vs. Local Metrics Comparison
  10. CWE Distribution & OWASP Mapping
  11. Language Statistics (C, C++, C#)
  12. Codebase Explorer with Line Highlighting
  13. Scanner Raw Output Viewer
  14. Audit Log & Security Trail
  15. Ollama Local Model Configuration
  16. Documentation Viewer (All 15 markdown docs)
  17. Evaluation Report Generator & Downloads
  18. Discrepancy & Anomaly Tracker
  19. Manual Triage Queue
  20. System Settings & Configuration

## 3. Architecture & Workflow

### Authoritative 7-Stage Workflow
```
1. DevGPT Dataset
        │
        ▼
2. Select C, C++, and C# Files
   Manually select the source code for analysis.
        │
        ▼
3. Analyze Code Using Security Scanners
   - Snyk
   - Semgrep
   - Flawfinder
   - Cppcheck
        │
        ▼
4. Process Scanner Reports Using Python
        │
        ▼
5. AI Tools
   - GPT Models (as described in the research paper)
   - Claude Models (as described in the research paper)
   - Local Offline Ollama (qwen2.5-coder:1.5b) as zero-cloud alternative
        │
        ▼
6. Ask AI Models to Identify and Repair Vulnerabilities
        │
        ▼
7. Calculate Detection and Repair Performance
```

## 4. Quick Start

### Prerequisites
- **Python**: 3.11+
- **Node.js**: 18+ (tested on v22.19.0)
- **Git**
- *(Optional)* Static Scanners: `flawfinder`, `cppcheck`, `semgrep`
- *(Optional)* Local AI: [Ollama](https://ollama.ai) with `qwen2.5-coder:1.5b`

### 1. Install Dependencies
```powershell
# Navigate to workspace
cd c:\Users\Deepu\OneDrive\Desktop\SECURE_CODING_WITH_AI

# Python dependencies
pip install -r backend/requirements.txt

# Frontend dependencies
cd frontend
npm install
npm run build
cd ..
```

### 2. Run Test Suite
```powershell
python -m pytest -v
```
*Expected: 16 passed in ~18s.*

### 3. Run Local Evaluation Pipeline
```powershell
python scripts/run_local_evaluation.py
```
This ingests dataset files, runs local scanners, executes vulnerability repair, and writes all 9 evaluation reports to `reports/`.

### 4. Start the Application
Open two PowerShell terminals:

**Terminal 1 (Backend API):**
```powershell
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```
- Interactive API Docs: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
- Health Endpoint: [http://127.0.0.1:8000/api/system/health](http://127.0.0.1:8000/api/system/health)

**Terminal 2 (Frontend Dashboard):**
```powershell
cd frontend
npm run dev
```
- Open browser at: [http://localhost:5173](http://localhost:5173)

## 5. Security Scanners Overview

| Scanner | Supported Languages | Local Status | Execution Method | Notes |
|:---|:---|:---|:---|:---|
| **Flawfinder** | C, C++ | Installed (`v2.0.20`) | Local CLI (`--csv`) | Zero-configuration offline AST scanner |
| **Cppcheck** | C, C++ | Not Installed | Local CLI | Download from official site if desired |
| **Semgrep** | C, C++, C# | Not Installed | Local CLI | `pip install semgrep` |
| **Snyk** | C, C++, C# | Not Installed | Local CLI / SARIF | Requires account auth; kept offline per strict rule |

*The pipeline handles scanner absence gracefully; missing tools are marked as unavailable and never crash execution.*

## 6. Generated Reports

After running `scripts/run_local_evaluation.py` or clicking **Generate Reports** in the web UI, the following files are produced in `reports/`:

1. `dataset_report.csv` – Ingested files, paths, languages, lines of code.
2. `scanner_results.csv` – Scanner runs, execution times, finding counts.
3. `normalized_findings.csv` – Every detected finding with rule ID, line, severity, CWE.
4. `cwe_distribution.csv` – Frequency of detected CWE categories.
5. `repair_results.csv` – Repair patches, engine types, rescan verification status.
6. `language_statistics.csv` – File counts, LOC, and findings aggregated per language.
7. `paper_benchmarks.csv` – Canonical export of all 18 paper tables.
8. `local_evaluation.csv` – Side-by-side metric comparison (Paper vs Local).
9. `final_evaluation_report.md` – Executive markdown summary.
