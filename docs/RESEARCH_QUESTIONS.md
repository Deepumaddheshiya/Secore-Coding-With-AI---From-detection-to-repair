# Research Questions and Evaluation Framework

This document details the three primary Research Questions (RQs) formulated in the study and outlines how the local implementation reproduces, maps, and evaluates each question.

---

## Research Question 1 (RQ1)

> **"How secure is the code generated by GPT in the DevGPT dataset?"**

### 1. Paper's Empirical Findings
- Analyzed 2,315 source files (44,943 lines of code):
  - **C:** 325 files, 7,449 LOC
  - **C++:** 990 files, 19,869 LOC
  - **C#:** 1,000 files, 17,625 LOC
- Static scanners initially generated **959 total detections** (21 Errors, 300 Warnings, 635 Notes/Info).
- Overlapping issues were identified in 114 files (141 detections).
- Detailed manual review by security researchers confirmed **56 genuine vulnerabilities across 48 files**.
- **Conclusion:** Real-world developer interactions with GPT yield significant security vulnerabilities. C was found to have the highest defect density (10.4 LOC/detect), followed by C++ (83.8 LOC/detect), while C# had the lowest (2,937.5 LOC/detect).

### 2. Implementation Mapping
- `DatasetService`: Ingests C, C++, and C# files from `data/devgpt/`. Computes LOC using blank-line and comment-filtering algorithms or `cloc`.
- `ScannerAdapters`: Executes available scanners (Flawfinder, Semgrep, Cppcheck, Snyk) locally.
- `FindingNormalizer`: Maps raw reports into a unified schema.
- `VulnerabilityReviewService`: Records manual confirmation decisions, distinguishing true vulnerabilities from false positives.

## Research Question 2 (RQ2)

> **"How effective are LLMs in detecting and correcting security issues when explicitly asked to do so?"**

### 1. Paper's Empirical Findings
- **October 2024 (GPT-4o Baseline):**
  - Confirmed vulnerabilities: 32 in 26 files (snapshot_20231012).
  - Detected: **18 / 32 (56.25%)**
  - Fixed: **17 / 32 (53.125%)**
- **September 2025 (Frontier LLM Evaluation):**
  - Confirmed vulnerabilities: 56 in 48 files across both snapshots.
  - **GPT-4.1:** Detected **46 / 56 (82.14%)**, Fixed **42 / 56 (75.00%)**
  - **GPT-5:** Detected **44 / 56 (78.57%)**, Fixed **44 / 56 (78.57%)**
  - **Claude Opus 4.1:** Detected **45 / 56 (80.36%)**, Fixed **43 / 56 (76.79%)**
- **Conclusion:** Detection and repair rates jumped from ~53–56% to ~75–82% over 11 months. However, LLMs regularly:
  1. Hallucinate non-existent CWEs with high linguistic confidence.
  2. Over-correct safe code (sycophancy).
  3. Require mandatory human supervision.

### 2. Implementation Mapping
- **Local Engine (No Cloud LLMs, No API Keys):**
  - Detects local **Ollama** service and locally downloaded models (e.g., `qwen2.5-coder:1.5b`).
  - Implements **rule-based AST/regex repair patterns** for confirmed vulnerability classes (e.g., bounds-checking for buffer overflows, `std::random_device` for `srand`, member initialization for constructors).
  - Interactive patch review: displays proposed diffs, requires explicit user approval before applying, creates backups, and rescans the file before/after.

## Research Question 3 (RQ3)

> **"Do developers provide more vulnerable code, or does GPT generate more insecure code during the interactions?"**

### 1. Paper's Empirical Findings
- **October 2024 Experiment:**
  - User-provided code: 10 vulnerabilities (31.25%).
  - GPT-generated code: 22 vulnerabilities (68.75%).
- **September 2025 Experiment (56 Confirmed Bugs):**
  - User-provided code: **25 vulnerabilities (44.64%)** across 23 files.
  - GPT-generated code: **31 vulnerabilities (55.36%)** across 25 files.
- **Model Performance by Source Origin:**
  - **User Code (25 issues):**
    - GPT-4.1: Detected 88.00% (22/25), Fixed 88.00% (22/25)
    - GPT-5: Detected 84.00% (21/25), Fixed 84.00% (21/25)
    - Claude Opus 4.1: Detected 76.00% (19/25), Fixed 76.00% (19/25)
  - **AI-Generated Code (31 issues):**
    - GPT-4.1: Detected 83.87% (26/31), Fixed 74.19% (23/31)
    - GPT-5: Detected 74.19% (23/31), Fixed 74.19% (23/31)
    - Claude Opus 4.1: Detected 83.87% (26/31), Fixed 80.65% (25/31)
- **Conclusion:** Both humans and LLMs introduce security flaws at similar frequencies in conversational programming. LLMs exhibit slightly higher precision repairing human code than performing self-inspection on AI-generated code.

### 2. Implementation Mapping
- Dataset metadata tracks `source_origin` (`user` vs `gpt3.5` vs `gpt4`).
- Interactive dashboard filters and aggregates findings by source origin.
